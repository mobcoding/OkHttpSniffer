OkHttpSniffer Plugin

Documentation and installation guide

OkHttpSniffer runtime library on JitPack

Maintained by mobcoding. Based on OkHttp Profiler by Eugene Tkachenko and Hanna Tkachenko.

No captured requests yet. Connect a device or emulator, select the app process, and trigger a request through an instrumented OkHttp client.

OkHttpSniffer shows request and response information from OkHttp directly in your Android Studio tool window. It also supports Retrofit requests made through the configured OkHttp client.

1. Install the IDE plugin

Install OkHttpSniffer in a supported Android Studio version and restart the IDE if prompted. Open an Android project. If you previously installed OkHttp Profiler, disable it while trying this fork to avoid duplicate tool windows.

2. For installation, include the runtime library in your app build.gradle.kts file

Add JitPack to your project's settings.gradle.kts dependency repositories:

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven(url = "https://jitpack.io")
    }
}

Add the runtime to the app module's build.gradle.kts:

dependencies {
    debugImplementation("com.github.mobcoding:OkHttpSniffer:1.1.4")
}

Your app must also supply OkHttp. The runtime is compiled against OkHttp 4.12.0 and uses Kotlin 2.2.0; ensure your app's Kotlin compiler can read its metadata. Do not keep the original io.nerdythings:okhttp-profiler dependency alongside this one, because the public package names are preserved.

For OkHttp

Kotlin

Add the interceptor in debug sources, and provide a no-op helper in release sources.

Create app/src/debug/java/com/example/app/network/HttpDebug.kt, using your own package name:

package com.example.app.network

import io.nerdythings.okhttp.profiler.OkHttpProfilerInterceptor
import okhttp3.OkHttpClient

internal fun OkHttpClient.Builder.configureHttpDebug(): OkHttpClient.Builder =
    addInterceptor(OkHttpProfilerInterceptor())

Create the release counterpart at app/src/release/java/com/example/app/network/HttpDebug.kt:

package com.example.app.network

import okhttp3.OkHttpClient

internal fun OkHttpClient.Builder.configureHttpDebug(): OkHttpClient.Builder = this

In shared app code, import the helper and configure the client used by your requests:

import com.example.app.network.configureHttpDebug

val client = OkHttpClient.Builder()
    .configureHttpDebug()
    .build()

Add a matching no-op helper for any other non-debug build types. A BuildConfig.DEBUG branch in shared sources does not make a debug-only dependency available to the release compiler.

Java

Create app/src/debug/java/com/example/app/network/HttpDebug.java:

package com.example.app.network;

import io.nerdythings.okhttp.profiler.OkHttpProfilerInterceptor;
import okhttp3.OkHttpClient;

public final class HttpDebug {
    public static OkHttpClient.Builder configure(OkHttpClient.Builder builder) {
        return builder.addInterceptor(new OkHttpProfilerInterceptor());
    }
}

Create the release counterpart at app/src/release/java/com/example/app/network/HttpDebug.java:

package com.example.app.network;

import okhttp3.OkHttpClient;

public final class HttpDebug {
    public static OkHttpClient.Builder configure(OkHttpClient.Builder builder) {
        return builder;
    }
}

In shared Java code:

import com.example.app.network.HttpDebug;
import okhttp3.OkHttpClient;

OkHttpClient client = HttpDebug.configure(new OkHttpClient.Builder()).build();

For Retrofit

Pass the configured client to your Retrofit builder:

Kotlin

val retrofit = Retrofit.Builder()
    .baseUrl("https://example.com/")
    .client(client)
    .build()

Java

Retrofit retrofit = new Retrofit.Builder()
    .baseUrl("https://example.com/")
    .client(client)
    .build();

4. Inspect requests

Connect an Android device with debugging authorized, or start an emulator. Run the debuggable app, open the OkHttpSniffer tool window, select its device and process, and trigger a request through the configured client. Select a request to inspect its headers, body, or JSON view.

To export data, right-click a request for copy actions or a JSON node for model generation. Generated models use Gson annotations; review the generated types before use.

5. If no requests appear

Check the device authorization, selected process, debug runtime dependency, and the exact OkHttp client instance used by the app. The runtime emits Logcat entries whose tags start with OKPRFL_. It does not capture WebView, other clients, or traffic from apps without the interceptor.

OkHttpSniffer 使用说明

在 Android Studio 中查看 OkHttp 请求、响应与 JSON。

完整文档 · 问题反馈

1. 添加依赖

在 settings.gradle.kts 的依赖仓库中添加 JitPack：

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven(url = "https://jitpack.io")
    }
}

在应用模块的 build.gradle.kts 中添加：

dependencies {
    implementation("com.github.mobcoding:OkHttpSniffer:1.1.5")
}

应用需已接入 OkHttp，支持 Android 5.0 及以上；构建工具需兼容 Kotlin 2.2.0 和 JVM 17。迁移时移除旧的 io.nerdythings:okhttp-profiler 依赖，避免重复类。

2. 仅在 Debug 启用

在应用模块中配置实际使用的客户端，无需创建 debug/release 两套文件：

import com.example.app.BuildConfig // 替换为应用模块 namespace 下的 BuildConfig
import com.mobcoding.okhttpsniffer.OkHttpProfilerInterceptor
import okhttp3.OkHttpClient

val client = OkHttpClient.Builder()
    .apply {
        if (BuildConfig.DEBUG) {
            addInterceptor(OkHttpProfilerInterceptor())
        }
    }
    .build()

请使用应用模块的 BuildConfig，不要导入依赖库的。若未生成此类，在应用模块的 android { buildFeatures { buildConfig = true } } 中启用。

implementation 确保 Release 编译也能找到拦截器；BuildConfig.DEBUG 为 false 时不添加拦截器、不输出抓包日志。依赖仍参与 Release 构建，R8 可能移除未使用代码，但不保证整个库被移除。不要将此示例的依赖改为 debugImplementation。

使用 Retrofit 时，将此客户端传入 Retrofit.Builder().client(client)。

3. 查看请求

连接已授权调试的设备或模拟器，运行应用的 debug 版本，在 OkHttpSniffer 工具窗口选择设备和进程，再发起请求。

点击请求查看响应和 JSON；右键请求可复制完整响应体或 cURL。长文本用 Previous / Next 翻页，Copy all 复制当前视图的全部文本；Raw 视图包含头信息。

没有请求时，检查所选进程和实际使用的客户端，并在 Logcat 搜索 OKPRFL_。仅捕获接入拦截器的请求；Logcat 丢失或断连可能导致内容不完整。

仅在调试版本启用，分享截图或日志前请移除 Token、Cookie 等敏感信息。
